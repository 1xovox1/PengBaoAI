# 鹏宝AI工作台：从 MVP 到工程化升级路线图

## 一、现状评估（MVP 阶段）

### 当前能力
- ✅ **统一入口**：工作台已搭建，Agent 超市、文件中心、权限审计基础框架已就绪
- ✅ **直播闭环**：播前生成、播后复盘、action 回填的数据结构与接口已就绪
- ✅ **投放闭环**：数据上传、日报生成、action 回填的数据结构与接口已就绪
- ✅ **Agent 工具化**：产品应用场景助手已实现“点选+填空 → Prompt → 生成话术”

### 当前短板（与大厂差距）
- ❌ **数据接入**：手动上传/粘贴，没有自动从业务系统拉数据
- ❌ **Agent 编排**：Agent 之间无法组合调用（例如：场景 Agent → 历史 Agent → 故事化 Agent）
- ❌ **指标体系**：只有基础审计日志，缺少成本、ROI、效果提升的完整看板
- ❌ **自动化工作流**：没有定时任务、自动触发、批量处理
- ❌ **数据中台对接**：没有统一的数据源，各业务系统数据分散

## 二、工程化 1.0（Q1-Q2）：让闭环真正跑起来

### 目标
**让 1-2 个试点负责人真正用起来，拿到“节省时间 + 采纳率 + 回填率”的数据证明价值。**

### 直播闭环升级路径

#### 阶段 1.1：数据输入半自动化（2-3 周）
**现状**：手动粘贴政策/价格、货盘、流量预期、主播状态

**升级方案**：
1. **模板化输入**：
   - 在“新建场次”表单里，增加“从模板加载”按钮
   - 预设几个常用模板（例如：三星 S 系列晚场、新品首发场、清库存场）
   - 模板包含：常用政策价格、货盘结构、流量预期范围、主播人设标签

2. **历史数据复用**：
   - 在“新建场次”时，可以“参考上一场次”：
     - 自动填充：平台、货盘结构、主播状态
     - 手动调整：政策价格、流量预期、目标

3. **文件上传增强**：
   - 支持上传“货盘 Excel”（SKU、卖点、库存、套餐）
   - 后端自动解析 Excel，提取关键字段，填充到表单

**交付物**：
- 前端：模板选择器 + 历史参考功能 + Excel 上传解析
- 后端：Excel 解析接口（`/api/live/parse-goods-excel`）

---

#### 阶段 1.2：Agent 编排（3-4 周）
**现状**：播前生成是一个“大 Prompt”直接调用模型

**升级方案**：
1. **多 Agent 组合调用**：
   - 播前生成改为“三步走”：
     - Step 1：调用“产品应用场景 Agent”（输入：货盘/政策/流量预期）→ 输出：应用场景话术模块
     - Step 2：调用“产品历史背景 Agent”（输入：产品系列/代际）→ 输出：历史故事模块
     - Step 3：调用“专业故事化 Agent”（输入：Step1+Step2 的输出）→ 输出：完整播前话术 JSON

2. **Agent 配置管理**：
   - 在 `server/.env` 或 `server/config/agents.json` 里配置每个 Agent 的 Dify Key
   - 后端新增 `server/services/agentOrchestrator.js`：
     - `orchestrateLivePre({ scenarioKey, historyKey, storyKey, inputs })`
     - 依次调用 3 个 Agent，把结果组合成最终 JSON

3. **前端展示优化**：
   - 在“播前生成”时，显示“正在调用应用场景 Agent... → 正在调用历史背景 Agent... → 正在调用故事化 Agent... → 完成”
   - 每个 Agent 的输出可以“单独查看/编辑”，再组合

**交付物**：
- 后端：`agentOrchestrator.js` + Agent 配置管理
- 前端：多步骤进度展示 + 分模块查看/编辑

---

#### 阶段 1.3：复盘数据自动接入（4-5 周）
**现状**：手动粘贴流量、数据表现、主播话术

**升级方案**：
1. **数据源对接**（先做“半自动”，再逐步“全自动”）：
   - **流量数据**：
     - 方案 A（半自动）：提供“流量数据模板 Excel”，运营填好后上传，后端解析
     - 方案 B（全自动）：对接抖音/天猫的“直播数据 API”（如果有），自动拉取场观、来源、投流/自然占比
   - **数据表现**：
     - 方案 A（半自动）：提供“GMV/转化数据模板 Excel”，运营填好后上传，后端解析
     - 方案 B（全自动）：对接你们的“销售数据系统”，自动拉取 GMV、转化、点击、停留、SKU 表现
   - **主播话术**：
     - 方案 A（半自动）：主播在“播中记录表”里填“关键异议点/话术版本”，播后上传
     - 方案 B（全自动）：对接“直播录制/字幕系统”，AI 自动提取关键话术片段

2. **数据清洗与标准化**：
   - 后端新增 `server/services/dataCleaner.js`：
     - `cleanTrafficData(raw)`：统一字段名（场观/来源/占比）
     - `cleanPerformanceData(raw)`：统一指标口径（GMV/转化/点击率）
     - `extractKeyScripts(transcript)`：从字幕/记录里提取关键话术

**交付物**：
- 后端：数据清洗服务 + Excel 解析增强
- 前端：数据上传界面优化 + 数据预览/确认

---

### 投放闭环升级路径

#### 阶段 1.1：数据清洗自动化（2-3 周）
**现状**：手动下载各平台数据 → 手动 Excel 清洗 → 粘贴关键指标

**升级方案**：
1. **多平台数据上传 + 自动清洗**：
   - 前端支持“批量上传”（抖音、天猫、京东、小红书等多个 Excel）
   - 后端新增 `server/services/adsDataCleaner.js`：
     - `cleanPlatformData(platform, rawExcel)`：按平台规则清洗
     - `mergeMultiPlatform(cleanedData)`：合并多平台数据，统一字段
     - `extractKPIs(mergedData)`：自动提取关键指标（花费、ROI、转化、点击率、成本、素材表现）

2. **字段映射配置**：
   - 在 `server/config/ads-field-mapping.json` 里配置每个平台的“字段映射规则”
   - 例如：抖音的“消耗” → 统一字段“花费”，天猫的“ROI” → 统一字段“ROI”

3. **清洗结果预览**：
   - 前端显示“清洗后的数据预览”（表格形式）
   - 用户可以“确认/调整”后再生成日报

**交付物**：
- 后端：`adsDataCleaner.js` + 字段映射配置
- 前端：批量上传界面 + 清洗结果预览

---

#### 阶段 1.2：日报生成 Agent 化（3-4 周）
**现状**：用一个“大 Prompt”直接调用通用模型

**升级方案**：
1. **接入你的“投放日报 Agent”**：
   - 在 `server/.env` 配置 `DIFY_API_KEY_ADS_REPORT`
   - 后端 `server/routes/ads.js` 的 `generate` 接口改为：
     - 优先调用你的“投放日报 Agent”（如果配置了）
     - 如果没有，fallback 到通用模型

2. **Prompt 优化**：
   - 把你的“投放日报 Agent”的 System Prompt 和知识库内容，整理成“Prompt 模板”
   - 后端根据“清洗后的数据 + 补充上下文”，动态组装 Prompt

**交付物**：
- 后端：Agent 调用逻辑 + Prompt 模板管理
- 前端：显示“正在调用投放日报 Agent...”

---

#### 阶段 1.3：数据源自动接入（4-5 周）
**现状**：手动上传 Excel

**升级方案**：
1. **定时任务拉取**（先做“定时导出”，再逐步“API 对接”）：
   - 后端新增 `server/jobs/adsDataSync.js`（用 `node-cron`）：
     - 每天 9:00 自动执行：从各平台“数据导出接口”（如果有）拉取昨日数据
     - 自动清洗 → 自动生成日报 → 发送到投放组企业微信/邮件

2. **数据源配置管理**：
   - 在 `server/config/dataSources.json` 配置：
     - 抖音：API 地址、认证信息、字段映射
     - 天猫：API 地址、认证信息、字段映射
     - 京东：API 地址、认证信息、字段映射

**交付物**：
- 后端：定时任务 + 数据源配置管理
- 前端：数据源配置界面（管理员可见）

## 三、工程化 2.0（Q3-Q4）：规模化与智能化

### 目标
**让闭环从“试点”变成“全公司标准流程”，并建立完整的指标体系。**

### 直播闭环升级路径

#### 阶段 2.1：智能推荐与优化（Q3）
1. **话术优化建议**：
   - 基于历史复盘数据，AI 自动分析“哪些话术模块效果好/差”
   - 在“播前生成”时，自动推荐“保留/删减/改写”的话术模块

2. **策略模板库**：
   - 建立“策略模板库”（例如：冲 GMV 策略、新品教育策略、清库存策略）
   - 用户选择策略模板后，自动填充“货盘结构/福利节奏/逼单话术”

3. **A/B 测试框架**：
   - 支持“同一场次生成 2-3 个话术版本”
   - 记录每个版本的“实际使用效果”（转化、停留、GMV）
   - 自动分析“哪个版本更好”，反哺下一场

---

#### 阶段 2.2：实时数据接入（Q3-Q4）
1. **直播中数据实时拉取**：
   - 对接抖音/天猫的“实时数据 API”
   - 在“直播中”Tab 显示：实时场观、实时转化、实时 GMV、实时弹幕关键词

2. **实时话术调整建议**：
   - 基于实时数据，AI 自动分析“当前话术效果如何”
   - 给出“实时调整建议”（例如：福利提前 2 分钟、加强某个卖点讲解）

---

#### 阶段 2.3：完整指标体系（Q4）
1. **效果看板**：
   - 展示：话术采纳率、复盘建议采纳率、action 执行率、GMV 提升、转化提升
   - 按“场次/周期/平台”维度筛选

2. **成本与 ROI**：
   - 记录每次生成的“Token 消耗/成本”
   - 计算“AI 生成成本 vs 人工成本节省”的 ROI

---

### 投放闭环升级路径

#### 阶段 2.1：异常检测与预警（Q3）
1. **自动异常检测**：
   - 基于清洗后的数据，AI 自动检测“异常指标”（例如：成本飙升、转化下滑、素材疲劳）
   - 自动生成“异常报告 + 处理建议”

2. **预警机制**：
   - 当检测到异常时，自动发送“企业微信/邮件”通知投放组
   - 包含：异常指标、可能原因、处理建议

---

#### 阶段 2.2：智能优化建议（Q3-Q4）
1. **预算优化建议**：
   - 基于历史数据，AI 自动分析“哪些人群/素材/时段效果好”
   - 给出“预算分配建议”（例如：泛人群预算降低 20%，精准人群预算提升 30%）

2. **素材优化建议**：
   - 基于素材表现数据，AI 自动分析“哪些素材类型/风格效果好”
   - 给出“素材制作建议”（例如：多制作“对比类”素材，少制作“纯产品展示类”）

---

#### 阶段 2.3：完整指标体系（Q4）
1. **效果看板**：
   - 展示：日报产出时间下降、异常发现提前量、action 执行率、成本下降、ROI 提升
   - 按“平台/周期/负责人”维度筛选

2. **成本与 ROI**：
   - 记录每次生成的“Token 消耗/成本”
   - 计算“AI 生成成本 vs 人工成本节省”的 ROI

## 四、大厂水平（2027+）：数据中台 + 自动化工作流

### 目标
**让 AI 工作台成为“数据驱动的业务决策中心”，而不是“工具集合”。**

### 关键能力

1. **数据中台对接**：
   - 统一的数据源（所有业务系统数据自动接入）
   - 统一的数据模型（直播数据模型、投放数据模型、销售数据模型）
   - 统一的数据服务（数据查询、数据清洗、数据分析）

2. **自动化工作流**：
   - 定时任务（每天自动生成日报、每周自动生成周报）
   - 事件触发（直播开始 → 自动拉取实时数据 → 自动生成话术调整建议）
   - 批量处理（批量生成话术、批量生成日报）

3. **智能决策**：
   - 基于历史数据，AI 自动推荐“最优策略”
   - 基于实时数据，AI 自动调整“执行动作”
   - 基于效果数据，AI 自动优化“生成 Prompt”

## 六、技术实现建议

### 数据存储升级（Q1-Q2）
**现状**：JSON 文件存储

**升级方案**：
1. **短期（Q1）**：继续用 JSON，但增加“数据索引”（例如：按平台/周期/负责人索引）
2. **中期（Q2）**：迁移到 SQLite（轻量、无需额外服务）
3. **长期（Q3+）**：迁移到 PostgreSQL/MySQL（支持复杂查询、高并发）

---

### Agent 编排框架（Q1-Q2）
**建议实现**：
- `server/services/agentOrchestrator.js`：
  - `orchestrateLivePre()`：直播前多 Agent 组合
  - `orchestrateAdsReport()`：投放日报 Agent 调用
  - `orchestrateLiveReview()`：直播复盘 Agent 调用

---

### 数据清洗服务（Q1-Q2）
**建议实现**：
- `server/services/dataCleaner.js`：
  - `cleanTrafficData()`：流量数据清洗
  - `cleanPerformanceData()`：数据表现清洗
  - `cleanAdsData()`：投放数据清洗（多平台）

---

### 定时任务框架（Q3）
**建议实现**：
- `server/jobs/` 目录：
  - `adsDailyReport.js`：每天自动生成投放日报
  - `liveWeeklyReview.js`：每周自动生成直播复盘
  - 使用 `node-cron` 或 `node-schedule`
